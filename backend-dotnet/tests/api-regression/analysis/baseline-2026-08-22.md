## Hallazgos de infraestructura corregidos

1. El Dockerfile restauraba toda `AcademiaDigital.sln`; al incorporar proyectos de tests a la solución, el build fallaba porque la capa de restore no copiaba sus `.csproj`.
2. `COPY . .` copiaba artefactos `obj/project.assets.json` generados en Windows y reemplazaba los restaurados dentro de Linux.
3. El contexto Docker incluía tests, documentación y configuración local innecesaria para la imagen productiva.

Se corrigió el Dockerfile para restaurar únicamente `AcademiaDigital.API.csproj`, publicar con `--no-restore` y copiar sólo `src/`. Se agregó `.dockerignore` para excluir `bin`, `obj`, tests, documentación, `.env` y `appsettings.Development.json`.

## Condiciones para repetir el baseline

- Usar `.env.example` o asegurar `E2E_DATABASE_NAME=AcademiaDigitalE2E` antes de ejecutar Docker Compose.
- La conexión SQL local E2E declara `Encrypt=False` y `TrustServerCertificate=True`; no se reutiliza para producción.
- `npm run e2e:reset` elimina exclusivamente el volumen `academia-digital-api-e2e_sqlserver_e2e_data`.
- `npm run e2e:down` detiene contenedores y red, pero conserva el volumen para diagnóstico.
